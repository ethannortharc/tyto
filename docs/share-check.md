# 共享屏幕验证

目的：确认 Tyto 的悬浮窗在 Zoom、Teams、Google Meet 共享**整个屏幕**时，对方看不到。

悬浮窗靠 `NSWindow.sharingType = .none` 隐藏。这个开关只是给截屏方的一个标记，截屏方可以不理它：Apple 开发者论坛有报告说 QuickTime 录屏（用 ScreenCaptureKit）会直接录到这种窗口（[thread 808016](https://developer.apple.com/forums/thread/808016)，FB21115847，2025-11 起没有结论）。所以每个会议软件都要实测。

## 编译和启动

```bash
scripts/build-app.sh ShareCheck
open build/TytoShareCheck.app
```

启动后有两个窗口，都开在当前活动的那块屏幕上（多屏时要共享这一块）：

- **悬浮窗**（右上角，半透明黑底）：开了共享保护，左上角有一块品红色标记，还有一个走秒的时钟。
- **对照窗口**（左上角，标题"Tyto 共享测试"）：普通窗口，不做隐藏，也带一块品红色标记。

## 一、本机自检

点"本机自检"，会用四种方式截屏，看两块标记有没有出现在截图里：

| 截屏方式 | 说明 |
|---|---|
| ScreenCaptureKit 截图（整屏，按窗口排除） | 最常见的整屏截图写法 |
| ScreenCaptureKit 截图（整屏，按应用排除） | 论坛报告里出现"时有时无"的那种写法 |
| ScreenCaptureKit 视频流 | 会议软件共享屏幕的做法，跑两秒取最后一帧 |
| 系统截图命令 screencapture | 系统自带的截图命令 |

第一次点会要求屏幕录制权限：系统设置 → 隐私与安全性 → 录屏与系统录音 → 打开"Tyto 共享测试"，然后退出 app 重开，再点一次。

还可以用 `--no-protect` 关掉共享保护再自检，这时每种方式都应该报"❌ 被截到"——用来确认自检本身认得出被截到的情况。

截图和 `report.json` 存在 `~/Library/Application Support/Tyto/share-check/<时间>/`，最近一次的结果另存一份 `latest.json`。也可以在命令行里跑：`open build/TytoShareCheck.app --args --self-check`，跑完自动退出。

每种方式的结果：

- ✅ 悬浮窗被隐藏：截图里有对照窗口，没有悬浮窗。
- ❌ 悬浮窗被截到了。
- 无效：截图里连对照窗口都没有，多半是没给屏幕录制权限。

## 二、Chrome 共享屏幕（不用开会）

```bash
scripts/chrome-share-check.sh             # 共享保护开
scripts/chrome-share-check.sh --no-protect   # 反向验证
```

临时开一个独立的 Chrome，用 `getDisplayMedia` 共享主屏（Google Meet 网页版和 Zoom、Teams 网页版都走这条路），取一帧看悬浮窗在不在。需要 Chrome 有屏幕录制权限：系统设置 → 隐私与安全性 → 录屏与系统录音 → 打开 Google Chrome。

## 三、会议软件实测

本机自检只能说明这几种截屏方式的结果，会议软件内部怎么截屏只有实测才知道。

准备：用手机或另一台电脑，换一个账号加入同一个会议，只用来看画面。

每个会议软件做三次：

1. **共享整个屏幕，共享保护开**：对方应该看得到对照窗口，看不到悬浮窗。
2. **共享整个屏幕，共享保护关**（在对照窗口里把勾去掉）：对方应该看得到悬浮窗。这一步证明测试是有效的——画面是实时的，悬浮窗的位置也在画面里。
3. **只共享一个窗口**（比如浏览器）：对方两个都看不到。

对方看到的时钟和本机一致，说明画面是实时的。另外在本机看一下：会议软件全屏时，悬浮窗还在不在最上面。

本机装的会议软件是飞书（Lark）。Google Meet 在 Chrome 和 Safari 里各测一次，两个浏览器截屏的实现不一样。会议软件的共享设置里如果有"截屏方式"之类的选项，把当前选的是哪个记下来。

## 结论怎么用

- 三家都 ✅：正式产品照这个做法。
- 有一家 ❌：在那家会议里改用"只共享窗口"，或者把悬浮窗放到不共享的那块屏幕上；产品里给出提示。
